## 已实现

### 1. 有效命中率奖励

状态：`v1.4.0` 已实现。

目标：奖励枪法稳定、有效输出高的玩家，但避免鼓励“少开枪刷命中率”。

当前实现：

- 不做裸命中率排名，只做小额加分。
- 只在玩家达到最低开火次数后计算，当前至少开火 `80` 次。
- 低于 `10%` 命中率不加分。
- `10%-20%` 加 1 分，`20%-30%` 加 2 分，后续每 10% 多加 1 分。
- 命中率奖励最高 `8` 分。
- 近战、投掷物、榴弹等不计入命中率统计。

当前配置：

```cfg
l4d2_mexp_w_accuracy_step "1.0"
l4d2_mexp_accuracy_min_shots "80"
l4d2_mexp_accuracy_floor "0.10"
l4d2_mexp_accuracy_step "0.10"
l4d2_mexp_accuracy_max_bonus "8.0"
```

### 2. 安全屋内倒地 / 死亡惩罚倍率

状态：`v1.5.0` 已实现。

目标：处理“已经进安全屋后，为了下一关复活状态而选择死亡”的情况。这个行为有时是合理策略，但完全不扣分可能会鼓励乱玩。

当前实现：

- 先只判断“已经进安全屋”的状态，不做“安全屋门口附近”的复杂距离判断。
- 玩家离开过起点安全区后，再进入 checkpoint 安全屋，会被视为进入终点安全屋。
- 终点安全屋内倒地/死亡，惩罚按倍率降低。
- `!mexp_round all` 会在 `[生存]` 行显示安全屋次数，例如 `倒地2(安全屋1)`；安全屋次数包含在总数内。

当前配置：

```cfg
l4d2_mexp_saferoom_incap_scale "0.10"
l4d2_mexp_saferoom_death_scale "0.10"
```

说明：

- 正常倒地仍按 `l4d2_mexp_p_incap` 扣分。
- 正常死亡仍按 `l4d2_mexp_p_death` 扣分。
- 安全屋内倒地/死亡只吃 `10%` 扣分。
- “安全屋门口附近”还没有做，仍然保留在后续计划里。

### 5. 大枪持用时间衰减

状态：`v1.7.0` 已实现，`v1.7.1` 扩展两把连喷并修正实际扣血统计，`v1.7.2` 拆分独立查询和阈值提醒，`v1.7.3` 支持恢复后重新提醒，`v1.7.4` 增加 `20` 秒重新提示缓冲。

- M16、SCAR、AK47、四类狙击枪和两把连喷按玩家、按枪种独立累计持用时间。
- 当前枪种每秒增加 `1` 秒，换下的枪种按恢复倍率逐秒回退。
- 同类武器共享时间，不能通过丢枪重拿清空；不同枪种独立升降。
- 步枪/狙击默认 `120-420` 秒衰减；两把连喷使用更慢的 `180-600` 秒衰减。
- 只影响特感和 Tank 的计分伤害，不改变原始伤害及其他事件分。
- 小枪、M60、榴弹、近战与爆炸类武器不参与衰减。
- `!mexp_weapon` 会显示当前枪种状态；每次从阈值下方重新跨入衰减或零倍率时分别提醒一次。
- 采用换枪回调和时间戳按需计算，没有加入每秒 Timer 或 `OnGameFrame`。

### 6. 全队掉分保护

状态：`v1.8.0` 已实现。

- 只在成功过关时判断，团灭不触发。
- 默认至少需要 `3` 名有效玩家。
- 结算前逐个比较“本关分 × 10”和玩家当前长期经验；只有所有有效玩家原本都会掉分时才触发。
- 触发后只降低负向更新影响，不改变本关评分和各项统计。
- 默认掉分影响倍率为 `10%`；与短图倍率或其他保护同时生效时取最低倍率，不相乘。
- 即使倍率设为 `0` 完全免除掉分，有效关卡数仍正常增加。

当前配置：

```cfg
l4d2_mexp_all_negative_guard "1"
l4d2_mexp_all_negative_min_players "3"
l4d2_mexp_all_negative_scale "0.10"
```

## 近期优先级较高

### 1. 辅助资源分

目标：奖励偏辅助型玩家在保血、补资源方面的贡献，尤其是给低血队友递药、打针或打包。

初步思路：

- 只奖励给队友使用资源，不奖励给自己使用。
- 只有目标队友血量较低时才给分，避免满血互递资源刷分。
- 可以区分“递药/针”和“打包”。
- 分数不宜太高，避免资源分超过救控、生存和输出贡献。
- 最好设置单关上限，防止特殊情况下互刷。

可能配置：

```cfg
l4d2_mexp_w_give_pills_lowhp "2.0"
l4d2_mexp_w_give_adrenaline_lowhp "2.0"
l4d2_mexp_w_heal_other_lowhp "5.0"
l4d2_mexp_support_lowhp_threshold "40"
l4d2_mexp_support_score_cap "15.0"
```

注意：

- 需要确认 L4D2 对递药、递针、打包队友的事件字段是否稳定。
- 可以先只做递药/递针和打包成功，不统计“丢地上后别人捡起”的情况。

### 2. 安全屋外主动死亡识别

状态：`v1.6.5` 已用更保守的方式部分处理。

暂时不建议直接做“有人进安全屋后，安全屋外死亡也减免本关分”的功能。

原因：

- 插件很难可靠区分“主动找特感紫砂”和“真的没防住被控死”。
- 主动自杀的人也可能故意去找特感，让死亡看起来像被控失误。
- 如果统一减免，可能鼓励玩家在收尾阶段主动送死，反而影响团队节奏。

当前替代方案：

- `v1.6.4` 已实现“成功过关低分保护”，只降低简单图过关后的长期掉分影响。
- `v1.6.5` 已实现“终点阶段安全屋外事故保护”，只降低最终过关时相关玩家的长期掉分影响。
- 安全屋内倒地/死亡仍按 `v1.5.0` 的安全屋倍率处理。
- 安全屋外死亡的本关扣分仍按正常死亡处理。

后续如果仍要处理，可以考虑更保守的方案：

- 只在全员已接近终点且确实成功过关时，对长期经验掉分做保护，而不是直接减少本关死亡扣分。
- 或只对“团队成功过关后的长期掉分”继续做保护，不对个人死亡行为本身做判定。

### 3. 终点安全屋锁分 / 防刷分

想法：玩家进入终点安全屋后，如果已经在安全屋内稳定停留一段时间，就认为这个玩家已经完成本关主要参与。此后不再继续获得加分，避免在终点安全屋里刷小尸、特感、Tank 伤害或其他输出分。

初步规则：

- 玩家进入终点安全屋后开始计时。
- 连续停留 `7` 秒后进入“锁分状态”。
- 锁分状态下：
  - 不再增加输出、击杀、小尸、Tank、Witch、石头、命中率等加分项。
  - 扣分项仍然继续记录，例如友伤、倒地、死亡、口水、Tank 拳、打铁等。
  - `!mexp_round` 可以显示锁分状态，方便确认。
- 锁分时在左下角聊天框提示该玩家，例如：
  - `[经验] 你已在终点安全屋停留 7 秒，本关加分已锁定。离开安全屋 5 秒后恢复。`
- 如果玩家离开终点安全屋，并且连续离开 `5` 秒，则解除锁分。
- 解锁后可以继续获得加分，用来支持“进门后又出去救人”的情况。

设计目的：

- 防止进安全屋后利用安全位置继续刷伤害分或小尸分。
- 不惩罚正常进门收尾。
- 保留出去救人的空间，避免玩家一进门就完全失去救援动力。

和现有安全屋内死亡倍率的关系：

- 这是“加分锁定”逻辑，不是“倒地/死亡减免”逻辑。
- `v1.5.0` 的安全屋内倒地/死亡惩罚倍率仍然保留。
- 锁分后如果玩家在安全屋内倒地/死亡，仍按安全屋内倍率扣分。
- 锁分后扣分仍会发生，所以不能靠进门锁分来免疫失误。

潜在风险：

- 有些图终点安全屋附近仍会刷特感或尸潮，过早锁分可能让守门/保护队友的人拿不到贡献。
- 如果门内有人负责开路或防守，锁分时间 `7` 秒可能需要通过测试调整。
- 需要确认 `player_entered_checkpoint` / `player_left_checkpoint` 在所有地图上的稳定性。
- 聊天提示不能太频繁，最好每次锁定/解锁只提示一次。

可能配置：

```cfg
l4d2_mexp_saferoom_score_lock_enable "1"
l4d2_mexp_saferoom_score_lock_delay "7.0"
l4d2_mexp_saferoom_score_unlock_delay "5.0"
l4d2_mexp_saferoom_score_lock_notice "1"
```

实现建议：

- 第一版只锁“加分项”，不要锁扣分项。
- 第一版只对已经进入终点安全屋的玩家生效，不影响安全屋外玩家。
- 如果后续发现会误伤救人，可以把锁分从“完全禁止加分”改成“加分倍率降低到 20%-50%”。

### 4. 高分顶满 / 分布压缩优化

现象：当前本关分数上限已经提高到 `600`，并在 `350` 分以上按 `0.5` 倍压缩，但在部分高压图、长图或团队发挥很好时，仍然会偶尔出现多人顶满的情况。

目标：减少“多个人都显示 600，看不出差距”的情况，同时避免把正常高光表现压得太低。

可选方案：

- **更强的高分段压缩**：保留当前 `350` 分软上限逻辑，但在更高分段再加一层压缩。
  - 例：`350` 以上按 `0.5` 计入，`500` 以上再按 `0.25` 计入。
  - 优点：改动相对小，容易理解。
  - 风险：如果压得太狠，高分玩家会觉得“打再好也没区别”。
- **非线性压缩**：高于软上限后不再线性增长，而是用平方根/对数一类的递减增长。
  - 优点：越接近上限越难顶满。
  - 风险：公式不如当前配置直观，cfg 调参解释成本更高。
- **分类得分上限**：给输出、Tank、小尸、清控/承压、辅助等类别分别设置单关上限。
  - 优点：能防止某一类数据爆炸把总分直接顶满。
  - 风险：需要重新梳理各类分数占比，改动比单纯压缩更大。
- **显示溢出分，结算压缩分**：内部保留一个“原始总分”用于展示实力差距，但长期经验只使用压缩后的结算分。
  - 例：显示 `本关 600 / 原始 742`，长期经验仍按 `600` 或压缩分更新。
  - 优点：玩家能看到高分之间的差距。
  - 风险：聊天信息会更长，可能需要继续拆行。
- **按地图时长或压力调整权重**：长图、高压图更容易爆分，可以根据时长或总特感压力降低部分重复项权重。
  - 优点：更贴近实际地图差异。
  - 风险：实现复杂，容易引入新的误判。

初步建议：

- 优先考虑“更强的高分段压缩”或“显示原始总分 + 结算压缩分”。
- 暂时不要直接继续提高 `l4d2_mexp_score_max`，否则长期经验区间也会继续膨胀。
- 如果只是偶尔顶满，可以先观察，不急着动；如果经常多人顶满，再安排后续小版本处理。

可能配置：

```cfg
l4d2_mexp_score_hardcap_start "500.0"
l4d2_mexp_score_hardcap_scale "0.25"
l4d2_mexp_show_raw_score "1"
```

## 中期可做

### 5. Tank 打铁误判过滤

当前打铁扣分要求伤害来源是物理物件，并且 `attacker` 是 Tank。正常情况下，玩家近战砍动小物件造成的 1 点碾压伤害不应该算作 Tank 打铁。

潜在风险：

- 某些地图小物件可能先被 Tank 或环境影响，再被玩家近战砍动。
- 如果游戏仍把物件伤害归属给 Tank，可能会把小物件 1 点伤害误记为一次打铁。
- 有些小物件可能连续造成多次 1 点伤害，误算时会放大扣分。

后续修正思路：

- 给打铁判定增加最低伤害阈值，例如低于 5 点或 10 点不计为打铁。
- 增加短时间冷却，同一个玩家在 0.5-1 秒内只记一次打铁。
- 尽量过滤质量很小或明显不是 Tank 常规打铁的物件。

可能配置：

```cfg
l4d2_mexp_tank_hittable_min_damage "5.0"
l4d2_mexp_tank_hittable_cooldown "0.75"
```

建议：

- 先继续观察 `!mexp_round all` 里的 `打铁` 是否异常。
- 如果出现“明明只是小物件蹭 1 点，却记了打铁”的情况，再优先修。

### 6. 特感助攻 / 单只特感最高伤

当前已经通过提高特感伤害权重、降低尾刀分，缓解了抢人头问题。后续如果仍然觉得尾刀影响偏大，可以再做更细的特感归属统计。

初步思路：

- 对每只普通特感记录各玩家造成的伤害。
- 特感死亡时：
  - 最后一击仍给少量分。
  - 达到最低伤害的人给助攻分。
  - 对该特感造成最高伤害的人给额外小分。

可能配置：

```cfg
l4d2_mexp_w_si_assist "0.3"
l4d2_mexp_w_si_top_damage "0.4"
l4d2_mexp_si_assist_min_damage "20.0"
```

注意：

- 这个功能比单纯改权重要复杂。
- 需要防止多特环境下统计过重或出现刷分。
- 建议等 `1.3.x` 当前权重经过一两晚测试后再决定。

### 9. 综合率统计：绝杀率 / 爆头率 / 防控率

状态：绝杀率已在 `v1.9.0` 实现，爆头率已在 `v1.10.0` 实现，两者暂不参与经验分；防控率仍为候选方向。

目标：在伤害、击杀和生存数据之外，补充能够反映技巧处理、瞄准质量和个人防控能力的比率指标。

#### 绝杀率

状态：`v1.9.0` 已实现统计展示。

参考公式：

```text
绝杀率 = (Hunter 空爆数 + Jockey 空爆数 + Charger 冲锋击倒数)
       / (Hunter 击杀数 + Jockey 击杀数 + Charger 击杀数)
```

说明：

- 分子只统计技巧播报插件明确判定成功的动作；Hunter 空爆由 `l4d2_stats 1.2.3-night` 确认后归给最后一击者，不单凭经验插件自己的普通死亡事件推断。
- Hunter 接收与聊天播报一致的飞扑途中空中击杀；Jockey 由 `l4d2_jockey_skeet 1.5-night` 提供回调；Charger 只统计冲锋中的近战击杀。
- `!mexp_round` 摘要显示百分比和辅助绝杀；`!mexp_round all` 保留三类次数与合计。当前默认分母不足 `20` 时标记“样本不足”。
- 成功过关和团灭都会显示达到最低样本的最高者；当前不加减本关分或长期经验。
- `v1.10.2` 新增 Hunter 辅助绝杀最高者播报；`v1.10.3` 将辅助范围与 `l4d2_stats` 的空爆播报对齐。辅助绝杀不进入绝杀率或评分。

#### 爆头率

状态：`v1.10.0` 已实现统计展示。

参考公式：

```text
爆头率 = 六类普通特感爆头击杀数 / 六类普通特感总击杀数
```

说明：

- 只统计 Smoker、Boomer、Hunter、Spitter、Jockey、Charger，不统计小僵尸、Tank 或 Witch。
- 直接读取六类特感 `player_death` 的 `headshot` 标记，不接入小僵尸事件，也不解析聊天播报。
- `!mexp_round` 摘要显示百分比；`!mexp_round all` 保留爆头数和六类特感总击杀。当前默认分母不足 `20` 时标记“样本不足”。
- 成功过关和团灭都会显示达到最低样本的最高者；当前不加减本关分或长期经验。
- 近战、爆炸物和燃烧等非爆头击杀保留在分母中，用于反映全部六类特感击杀中的爆头占比。

#### 防控率

参考公式：

```text
防控率 = 防控次数 / (防控次数 + 被控次数)
```

候选防控动作：

1. 推停正在飞扑自己的 Hunter。
2. 推停正在飞扑自己的 Jockey。
3. 推停正在呕吐自己的 Boomer，并且没有被喷中。
4. 砍断 Smoker 吐向自己的舌头。
5. 被 Smoker 绑住时成功推开 Smoker。
6. 以自己为目标的 Charger 冲锋未能撞中。
7. 空爆正在飞扑自己的 Hunter。
8. 空爆正在飞扑自己的 Jockey。
9. Smoker 的舌头尚未绑住自己时将其击杀。
10. 击倒正在冲向自己的 Charger。
11. 安全解决以自己为目标的 Boomer，并且没有被喷中。

归属边界：

- 只有当前控制技能的目标确实是该玩家时，才能算该玩家成功防控或被控。
- Hunter 以玩家 A 为目标、飞扑途中被玩家 B 空爆时，不能算玩家 A 防控成功；玩家 B 的行为继续按现有团队救控或技巧逻辑处理，不混入 A 的个人防控率。
- 已经倒地的玩家没有正常反抗能力，继续沿用“倒地后不累计吃控次数和被控时间”的规则，不加入防控率分母。
- 同一次攻击只能在防控或被控中记一次，必须防止事件回调重复计数。

#### 接入经验分的建议

- 绝杀率和爆头率均只统计展示，不直接加减经验分；`v1.10.4` 起默认查询合并到 `[比率]` 行，完整查询保留分项。
- 防控率后续实现时，再评估是否新增独立 `!mexp_rate`，避免继续增加 `!mexp_round` 行数。
- 单关样本不足时显示次数但不显示有效率，或标记为“样本不足”。
- 如果后续参与计分，只做达到最低样本后的少量阶梯奖励，并设置单关上限，不因低比率直接扣分。
- 绝杀和防控动作中有一部分已经获得技巧分，若再按比率奖励，必须避免对同一行为重复给过高分数。
- 这三项受枪械、站位和团队职责影响明显，应先经过多晚实测，再确定最低样本、权重和加分阈值。

绝杀率已按回调方式接入，Hunter 使用 `l4d2_stats` 与聊天播报共用的判定事件，爆头率直接读取六类特感死亡事件；两者都没有解析聊天文字。防控率实现前仍需审计 `l4d2_skill_detect` 与 `l4d2_stats`，缺失的 Jockey、Charger、Boomer 目标判定再补充。

## 暂时不建议优先做

### 10. 安全屋门口附近的倒地 / 死亡判定

这个比“已经进安全屋”难很多，因为需要判断玩家是否接近安全屋、地图流程是否接近终点，容易误判。

建议：

- 先做安全屋内惩罚倍率。
- 如果仍然不够，再考虑更复杂的“接近安全屋”判断。

### 11. 命中率扣分

暂时不建议做。

原因：

- 多特服里压枪、扫射、预瞄、穿尸潮都很常见。
- 单纯低命中率扣分可能惩罚负责控场和清潮的人。
- 先做小额命中率奖励更稳。
